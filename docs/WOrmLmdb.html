WOrmLmdb

WOrmLmdb

new WOrmLmdb(optopt) → {Object}

Description:

  • 操作資料庫(LMDB)

    回傳物件為EventEmitter，除各操作函數外另發出change與error兩事件，供呼叫端於單一處集中觀察資料異動與失敗。 事件僅為附加通知，其所送出之資訊皆另有正規管道(操作結果經resolve、整批性錯誤經reject、逐筆失敗經該筆之err欄位)， 故不監聽亦能取得完整資訊，且監聽與否不改變任何操作之回傳值。

    change事件，參數為(mode, data, res)，於資料實際異動成功後發出： mode為操作別字串，可為'insert'、'insertBulk'、'save'、'del'、'delAll'；save內若逐筆走自動插入則該筆另發出mode為'insert'之事件，於整批定案後、整批事件之前發出。 data為本次操作之輸入數據，delAll固定為null。 res為本次操作之回傳結果之複本，改寫之不影響回傳結果。 逐筆函數以整批為單位發出一次而不逐筆發出，select與selectByPk不發出本事件。

    error事件，參數為(mode, data, err)，於操作發生錯誤時發出： mode為操作別字串，可為'select'、'selectByPk'、'insert'、'insertBulk'、'save'、'del'、'delAll'、'backup'。 data為本次操作之輸入數據，無輸入數據者為null。 err為錯誤訊息字串，內容與正規管道所送出者一致。 整批性錯誤於reject之前發出；逐筆失敗於整批定案後依序發出，每筆一次，整批因整批性錯誤而reject者不發出。 註: 逐筆失敗時整批仍resolve，故收到本事件不表示該次呼叫失敗；正常結果(如查無數據、主鍵未命中、全數已存在)不發出本事件。

    讀取(select、selectByPk，以及save、del、delAll內之讀取)可見本次呼叫前已提交之資料，含同一程序之其他實例與其他程序之提交；惟select於useCache開啟且快取命中時回傳快取。

    主鍵(id)經LMDB鍵編碼後不可超過1978位元組(UTF-8；首字元碼小於28者另計1位元組跳脫)：insert與insertBulk遇之整批reject而不寫入任何一筆，save該筆ok為0； 讀取側(selectByPk、del與save內之讀取)對超過者一律視為未命中。 註: 值非物件之紀錄(他方寫入)於insert與insertBulk視為已存在(以鍵判定)，於selectByPk、save與del視為不存在。

    字串良構(w-orm系列規則，wsemi之chkOrmStr與chkOrmData): LMDB之值編碼會把孤立代理字元(String.prototype.isWellFormed()為false)改寫為三個U+FFFD， 使寫入值與讀回值不同、文件內相異鍵名撞鍵而靜默覆蓋、讀回之id無法再定址該列，故於任何讀取與寫入之前拒收：

    1. 主鍵(id)不得含孤立代理字元與NUL，不隨autoGenPk改變；
    2. 寫入資料(insert、insertBulk、save)之字串值與鍵名(含巢狀物件、陣列元素、Map與Set之項目、Error與RegExp之文字)不得含孤立代理字元，值與鍵名之NUL不拒；
    3. opt.url、opt.db、opt.cl含孤立代理字元者於建構時throw，訊息為invalid opt.<名>: string contains lone surrogate。 處置與無效主鍵同形：insert與insertBulk整批reject而不寫入任何一筆(error事件先於reject)，save與del該筆ok為0並附err(同批其他筆照常)，selectByPk回null； 訊息為固定詞彙而不回顯值：invalid id: 原因 at [data[k].id]、invalid data: 原因 at [data[k].路徑](k為批次索引，單一物件為0；不合格之鍵名以標示)， 原因為string contains lone surrogate、string contains NUL(僅主鍵)、not a string或string is empty(del之id未給、非字串或空字串)。 U+FFFD本身與成對代理(emoji等)為良構，照常接受。既有資料不遷移，檢出與清除法見README。

    一致性備份(w-orm-lmdb專屬擴充，系列其他後端無對應函數): backup(fpTar, { compact })以LMDB環境複製產生某一提交點之完整快照，服務運行中(本程序或另一程序寫入)亦一致，詳見backup之說明與README。

(async, static) backup(fpTar, optionopt) → {Promise}

Description:

  • 一致性備份(w-orm-lmdb專屬擴充, 系列其他後端無對應函數)

    以LMDB之環境複製(mdb_env_copy, lmdb-js之backup)產生本資料表之備份: 複製於讀交易下進行，所得為某一提交點之完整快照， 本程序或其他程序同時寫入不致產生撕裂(直接複製或壓縮data.mdb可能讀到寫入中之頁面而不一致)，亦不阻擋寫入。 快照含呼叫前已await完成之寫入；呼叫當下進行中而未完成之寫入不保證含入。備份進行期間環境保有一個讀交易，期間被覆寫之頁面不被回收，資料庫檔可能暫時增大。

    目標fpTar為資料夾：不存在時(含其上層)自動建立；已存在時須為空資料夾，否則整批reject而不寫入任何東西(不覆蓋、不合併)； 不得為本資料表自身之資料夾或其內(以實體路徑比對，經符號連結或連接點之別名亦同)。完成後目標內只有data.mdb(不含lock.mdb)，其為完整之LMDB資料庫檔， 還原法為將data.mdb置於資料表資料夾(url/db/cl)內以WOrmLmdb開啟，或直接以lmdb開啟該目標資料夾。 備份先寫於目標內之暫存子資料夾，完成後再確認目標內除該暫存夾外別無他物(備份期間他處於目標內建立東西者整批reject且不動該東西)，才以改名將data.mdb移入目標、再刪暫存子資料夾，故目標內出現data.mdb即表示複製已完成； 失敗時移除暫存子資料夾，並自目標向上逐層移除本次所建立之資料夾(僅限空資料夾，他處於其內建立之內容不刪)，已存在之空目標資料夾原樣保留。

    fpTar須為非空字串且良構(不含孤立代理字元與NUL，與系列字串良構規則一致)，否則整批reject，訊息為invalid fpTar: 原因(原因同主鍵：not a string、string is empty、 string contains NUL、string contains lone surrogate)。已關閉之實例整批reject。錯誤皆於reject之前發出一次error事件(mode為'backup'，data為null以不回顯路徑)，不發出change事件(不異動資料)。 備份進行中呼叫close()會等候備份結束後才關閉環境，期間實例已視為已關閉而拒絕新操作。

    註: 以另一程序備份時，於該程序以同一url、db、cl建構實例後呼叫本函數即可(讀取可由任意多個程序進行)；建構不存在之資料表會建立空環境，請只對既有資料表備份。

(async, static) delAll(findopt) → {Promise}

Description:

  • 依條件刪除多筆數據(破壞性操作，須審慎使用，非必要不用；刪除單筆請用del)

    使用須知:

    1. 不給條件即刪除全部數據: find未給、為undefined或為{}時，刪除資料表內全部數據，不另行確認。 給了條件才是部分刪除。
    2. 傳了值卻不是條件物件(null、陣列含[]與[{...}]、字串、數值、布林、函數、Date、RegExp、Map、Set、類別實例等) 一律整批reject，不視為{}，不刪除任何數據。
    3. 條件僅支援系列白名單: 欄位等值{欄:純量}(多欄為AND)、欄位運算子$eq $ne $gt $gte $lt $lte(值為純量)與 $in $nin(值為純量陣列)、文件層$and $or(值為條件物件之非空陣列)。純量為字串(不含NUL字元與孤立代理字元)、有限數字、布林、有效Date； null僅可用於欄位等值、$eq、$ne。白名單外之運算子($not $nor $regex $options $exists $where $expr $like $ilike等)、 欄位層$and/$or、子查詢、函數值、Symbol鍵、undefined值、空的$nin/$and/$or等一律整批reject， 訊息為invalid find: 原因 at [路徑]，且不刪除任何數據。
    4. 與select共用同一檢核與同一條件，select(find)命中之數據即本函數刪除之數據； 建議先以select(find)確認命中範圍再刪除(useCache開啟且他方已寫入時，select可能回傳快取，而本函數一律直讀資料庫)。
    5. 條件值若來自可能為undefined、null或空陣列之變數，呼叫端須先自行判斷；undefined值會reject而非被忽略， 空的$nin會reject，$in:[]則為恆假(刪除0筆)。
    6. 語意差異(依後端，見README): MongoDB式: $ne(比較值非null時)與$nin會命中欄位為null或缺欄之數據，$ne:null則排除之； 欄名同於Object.prototype成員(constructor、toString等)者，數據無此自有欄位時視為缺欄。 需明確表達時可用可攜寫法: 排除NULL為{$and:[{f:{$ne:null}},{f:{$ne:x}}]}，含NULL為{$or:[{f:null},{f:{$ne:x}}]}。

    n與nDeleted皆為實際刪除筆數，不取全表筆數。條件無命中時回{n:0,nDeleted:0,ok:1}，不視為錯誤。 處理中途發生整批性錯誤(如操作進行中被close)時整批reject，先前已刪除之筆不回滾，呼叫端須重新讀取確認；刪除依資料庫之實際鍵。

(async, static) insertBulk(data) → {Promise}

Description:

  • 批次插入數據，全批視為一個單位，全部插入成功或一筆都不寫入；主鍵衝突以外之整批性錯誤(同insert)亦於任何寫入之前檢出而reject 註: 本函數非insert之加速版，兩者衝突政策不同。insert於主鍵已存在時跳過該筆而整批ok為1， 本函數則整批reject且不寫入任何一筆；同批含重複主鍵者亦視為衝突。確無衝突時兩者結果相同 註: 於本套件不會較insert快，因insert本即以Promise.all一次送出全部條件寫入而非逐筆await， 提供本函數係為與其他w-orm系列套件維持同一組函數，令呼叫端得於各套件間替換而不須改寫呼叫

Description:

  • 儲存數據

    預設以主鍵為準將輸入深層合併進既有數據(未給之欄位保留，陣列欄位依索引逐元素合併)，無法刪除欄位； option.merge給false則改為整筆覆寫：各筆於同一個LMDB寫交易內以輸入整筆取代既有數據，舊數據中不在輸入內之鍵不保留，陣列欄位整筆替換， 不經刪除故無[刪後插前]之空窗，寫入失敗(如數據無法序列化)時原數據仍在。merge為w-orm-lmdb之選項，系列其他後端未提供。 存入內容為輸入經LMDB編碼器往返後之結果，型別與欄名之保真範圍同insert與預設save(如Set讀回為陣列，自有欄名__proto__與__proto_會併為一鍵)
